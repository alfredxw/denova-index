# 示例资源包

## 照夜长河 · 大世界修仙模拟

定位是可长期生活与发展的**大世界修仙模拟设定**。从凡人问仙走到宗门晋升、散修经营、百艺传承、跨域远游，乃至渡劫飞升；没有唯一主线，也不要求玩家集齐人物、榜单或秘境。世界通过时间、资源、人物动机与已经发生的事实保持连续。

### 世界与成长

| 区域 | 生活与资源 | 势力及长期矛盾 |
| --- | --- | --- |
| 东陵 | 入门修炼、宗门生活、丹药与坊市 | 悬锋剑宗、合欢宗、抱朴谷、宋氏与千灯楼；峰脉、师承与资源竞争 |
| 赤砾原 | 炉城、矿路、器材与匠艺 | 百炉盟；公共炉位、矿供与新旧工艺 |
| 玄霜岭 | 雪舟、寒玉、药谷与人妖边市 | 寒汀门和霜羽盟；矿业、雷流与迁徙界约 |
| 沧溟海 | 航海、养珠、海药与遗府 | 潮生会和鲛绡庭；航路、产珠海沟与救援 |
| 中土 | 进阶传承、跨域阵台与护界 | 镜川书院、归衡院及灰契社；知识、禁术与接引资源 |
| 青阙仙域 | 仙元转化、界航与仙材研究 | 落星接引司、照界园；接引、居留与修行投入 |

统一序列：凡人 → 炼气一至十层 → 筑基 → 金丹 → 元婴 → 化神 → 返虚 → 合体 → 大乘 → 渡劫 → 真仙 → 仙帝 → 超脱。渡劫是飞升阶段，没有初中后期；其余分期及能力依资料说明。仙境仅保留这三境，不细分小境界，内容以凡界为重。

功法区分初学、熟练、精通，记录可用招式与剩余瓶颈；剑诀、合欢修法各有分支、配套与弱点，旁门传承提供有代价的选择。成长包含功法、身体与心神、资源、时间、护持和实际瓶颈。境界寿元不等于固定死亡日期，突破不会把年龄归零；高阶能力也有距离、承载与消耗。灵根、体质、神魂、丹器符阵、器物使用与宗门贡献各有资料，不以一次高点数替代必要条件。

### 可选开局与自定义角色

| 开局 | 初始处境 | 眼前选择 |
| --- | --- | --- |
| 既有人物·此刻启程 | 沿用所选角色的身份、修为与经历 | 从近期目标展开，等待玩家选择 |
| 凡人·山村问仙 | 成年药铺学徒，未引气、未测灵，升仙舟次日将行 | 陆照棠甩开追兵，以半册功法换藏身半夜 |
| 合欢·初入红尘 | 炼气二层外门弟子，尚无同修搭档 | 阮绯舟踏火设赌，纪含章试铃另邀席位 |
| 剑宗·败峰新徒 | 炼气二层藏锋崖新徒，刚拿到修好的旧剑 | 顾停云提出用修缮费换一次假赛 |

这四个只是便于开始的可编辑预设，不是资料库规定的角色或路线。用户可以创建自己的角色，也可以扮演既有人物，自定合理的地域、境界、时间与处境。具体身份、初始行装、相遇场面和倒计时只写在所选预设或用户自定义内容中。选为玩家角色的人物不再作为独立 NPC 行动；未明确修改的经历与关系可以沿用，行动与选择仍由用户控制。

推荐主角为孟迟（男，炼气六层散修）、纪含章（男，炼气八层合欢宗弟子）、顾停云（男，炼气二层剑宗新徒）、宋问渠（男，筑基后期世家修士）、陆照棠（女，炼气九层散修）和祝清砚（女，筑基中期剑修）。六人带“主角”标签并设为主要角色，其余人物仍可选择。自建合欢新人默认成年男弟子，性别可编辑。

源文件按世界、势力、地点、人物、功法器物组织，人物先列六位推荐主角，再聚拢相关人物。主程序导入后按重要程度、类型、名称排序，因此推荐主角优先，同级名称顺序由主程序决定。在仅导入本包的新作品中，孟迟是按当前排序规则出现的首位推荐人物；已有作品可能受其他主要角色影响。

扮演既有人物建议选“既有人物·此刻启程”。其他三个开局也包含身份适配说明，防止重置为新人或生成同名 NPC；扮演顾停云时，不把假赛视为已经发生的行为。适配属于叙事指令，仍需模型试玩检查。

### 人物封面与场景背景

七位人物配有示例封面：陆照棠、祝清砚、阮绯舟、柳听蝉、花知宁、苏晚禾、裴照雪。图片通过资料素材集合与封面字段导入；男性角色暂不配图。画面仅作外貌参考，不规定故事中的地点、时辰或已发生的动作。

世界总览“照夜长河”附带五类横幅背景。按反复使用的活动空间选图，供不同人物、地点和境界的故事复用，不按五域各配一张。住处、坊市和庭院承载日常循环，山河用于远景与行旅，遗迹用于阶段性连续探索。

| 素材 | 画面与适用场景 |
| --- | --- |
| 照夜长河·通用背景 | 保留黄昏远山、长河、临水镇落与仙门；适合开局全景、临水停留、远眺和相近山河间的行旅 |
| 照夜长河·起居雅室 | 木石内室，清楚可见的床榻、寝具与半开帘帐，配案几、屏风和打坐空间；适合洞府居室、宗门住处或客舍上房中的修炼、休息、疗伤、密谈与成年人亲密相处 |
| 照夜长河·坊市街巷 | 铺面、摊位、廊檐与石板街；适合清梧镇、松烟坊及相近聚落的交易、委托、消息、邂逅、追逐和冲突 |
| 照夜长河·庭院石坪 | 开阔石坪、木廊与少量树木；适合宗门院落、宅院或客舍庭院的授业、练功、比试、会面与聚会 |
| 照夜长河·遗迹内景 | 古旧石殿、石柱、台阶与回廊；适合古府、旧殿或地下遗迹的探索、调查、寻宝、对峙与斗法 |

新增背景没有人物、可读文字或专属势力标识，也不预置宴席、战斗、宝物或机关结果。柔和光线与中央留白便于叠加正文和人物立绘。通用范围以实际空间为界：庭院不能准确代表镜湖桃宴，普通遗迹也不代表冰湖、海底或熔岩地带。图片素材不建立故事事实。

五张背景复用现有资料素材与背景选择能力。导入时可采纳原通用背景为本书的新故事默认值，也可在故事设置中手动选择其他背景；开启动态背景后，Agent 可依据当前场景与素材说明选择，切换仍取决于模型。关闭动态背景可持续显示所选背景。推荐项不会覆盖已有故事或未经确认的书籍设置。

新增四张以 WebP 分发，合计约 0.91 MiB；保留原 PNG 默认图后，五张背景合计约 3.26 MiB，低于新增 3 MiB、全部背景 6 MiB 的制作预算。不增加昼夜、季节或五域专属变体。横幅在窄屏下会裁切，起居雅室的床榻偏右，可按需调整背景焦点。

素材需要支持资料素材集合与故事背景选择的 Denova 版本。图片位于 `examples/cultivation-starter/assets/`，由内置 image_gen 生成，完整提示词保存在同目录的 `prompts.json` 中。

### 世界如何推进

- **时间与人物**：长时间闭关、养伤或远行前核对补给、年龄和到期约定。只推演有关人物与势力的有限变化：修炼、迁居、继承、经营、失利或衰老；不逐日生成全世界流水账，也不让所有人等待玩家。
- **信息与因果**：通过见证、传讯、公告和现场痕迹获知远方结果，消息会滞后。高阶人物也不能读取全部秘密，追索必须有信息、能力和时间。
- **秩序与风险**：宗门、坊市和荒野的保护不同。失败可以损失材料、受伤、被俘，明确的致命风险也可导致死亡；不凭空救援，不因普通失误随意判死。原生规则使用 `hard_failure`，后果与实际风险相称。
- **经营与生活**：价格有当地基准，产业需材料、租金、维护和合伙分成。记录净收益，允许稳定生活与真实成果，不自动无限产钱，也不每次休息都派人夺宝。
- **世界连续性**：死亡、离宗、突破、宝物易主和秘境采掘结果留在本故事。十二年后再进沉霞丹府，不会重置已取走的异火本源。榜单只是公开消息形成的评议，不是全知实时面板。

这是交给模型和 Denova 原生工具使用的设定与预设，**不是新开发的自动世界模拟引擎**。没有现实时间后台推进、独立排行榜数据库、HTML 状态栏或旧变量补丁协议。

### 可反复参与的玩法

- **修行**：先确定一个可观察的成果，再选择静修、求教、历练或同修；结算耗时与积累，已解决的瓶颈不会无故重置。平稳修炼可合并推进，突破后展示实际新能力。
- **功法**：引灯诀用于感气与恢复；听隙剑诀可从留半步发展到听阵、回澜，形成应对不同敌手的办法；心弦合息诀可走独修辨念或同修配合。招式有用法、条件与弱点，不只更换名称。
- **探索**：可选择外围取药、深入取传承、合作分火或勘路后撤。成果能炼化、修复、交易和投入下次行动；对手也会行动，秘境不会无限重置。
- **宗门**：比试、作品考核和长期职役都能提供资源与权限。接任后可授业、安排有限人手或经营资源，责任与收益一起变化。
- **经营**：明确一批订单的工时、成本、产量与售价。例如十四枚灵石成本、六颗丹每颗三枚，全售净余四枚；未售库存不当作收入。改良、复购和设备影响后续生产。
- **交游与生活**：同伴主动邀练、传讯、探望或商议合作；分工、合击、共享洞府与经营产生实际收益，情缘与信任从经历发展。灵兽可以培养寻踪、护送、采集等专长。

内容回归时关注这些场景：自定义高阶人物不退回新人身份；一次静修兑现约定成果；少成丹按实际批次结算；秘境提前撤离保留已得收益；扮演既有人物时不出现同名 NPC；两榜更新必须有公开消息。这些是实际模型试玩的检查点，静态资源与导入测试不证明长期叙事效果。

### 人物、秘境与长期目标

共 31 位人物。条目中的年龄、境界和身份是故事起点或初遇参考，不是终身定值；若已有时间推演，初遇时沿用推演结果。人物可从筑基逐步修至金丹乃至仙帝或超脱，也可能停滞、跌境或身亡，各故事线独立发展。当前境界、能力、寿元和职责以本故事已确认进展为准，不因重读资料回退，不回写共享资料。

31 位人物围绕鲜明气场、独有战法与代表事迹展开：低阶修士有狠劲、奇招与成名作风，宗主、掌门及高阶人物以具体战绩建立威势。外貌、功法、器物、血脉与性格互相呼应，少数人物另列特殊体质；招式先呈现作用，再交代必要条件与代价。原有身份、参考境界、师承、榜单和法宝归属沿用，人物行事依欲求、立场与恩怨展开。

人物卡中的 `{{user}}` 指本故事主角。仅个别人物单列旧识或情缘起点，其余关系由实际相遇与选择展开；陆照棠的清梧旧识只在选用该背景时成立，纪含章可以主动相邀，道侣身份须由双方在故事中确认。若玩家扮演该人物，资料中的性格与事迹作背景参考，行动、对白、内心和承诺由玩家决定。江雁回与祁朔保留一次救舟旧交，师承、公开约战与普通生意往来各有实际缘由。

六处试炼与探索节点各有进入条件、时序、退路和收益：问剑旧台、沉霞丹府、烬轮窟、北天镜湖、潮返岛与沉舟庭、望阙台（青阙照界园随飞升展开）。它们是受管或有主之地，不伪装成无人认领的宝箱；部分可多人有所获，部分核心资源有限，合作与独占会留下不同后果。

千灯楼只编撰天骄榜与绝色榜。天骄榜连接公开战绩、同辈挑战与招揽，绝色榜连接风姿、才艺、宴请与人情；名次不决定胜负或感情。宝物和异火保留来源、能力、归属与培养方式，价值依据实际用途判断。人物感情基于相处，亲密关系参与者均为成年人并自愿选择。

### 内容与文件

- `lore.json`：78 项，含 12 项世界与修行资料、13 个势力、12 处地点、31 位人物、10 项功法器物。附带六组资料索引，世界总览全文常驻，其余 77 项展示查阅简介、按需读取正文，保留原有资料 ID。
- `openings.json`：四个可选开局，依赖资料集合；资料集合不依赖或指定其中任何开局。
- `narrative.json`：大世界模拟、时间推演、人物自主目标、视角和玩家控制边界。
- `actor-state.json`：13 个原生字段，覆盖境界、功法、位置、伤势、财物、约定、交游、时历、年龄寿元、资质、灵力心神、身份贡献及洞府产业。不把所有世界人物复制到玩家状态。
- `rules.json`：依据实际能力和准备处理不确定性，允许真正失败与相称后果。
- `events.json`：18 类际遇；在原有 12 类上加入经年闭关、跨域远行、产业经营、界约谈判、传承交接和飞升。事件只在条件成立时使用，不是自动倒计时。
- `illustration.json`：覆盖五域与仙界的场景和人物连续性。
- `skills/book-analysis/`：独立的通用中文拆书 Skill，适用于各种小说题材。
- `skills/lore-creation/`：可独立选装的通用资料创建 Skill，附角色与设定分节指南，适用于写作与游戏的资料创作。

正文以意象立世界、四字句定调，防呆条款只保留必要规则：成败须有条件与代价、秘境不重置、死亡不复活、情缘须自愿、榜单依消息。内容计数涵盖上述七个内容 JSON 的所有字符串值（连同名称、关键词、ID 等）及两个 Skill 的正文和引用文件，上限 70,000 个 Unicode 字符；不计 JSON 结构、分发元数据、许可证和本说明文档。此处计数不是模型 token 数。

### 资料创建 Skill

`lore-creation` 随本包分发，可单独选装，不依赖照夜长河资料，也不限定修仙题材。指令与分节指南使用中文，生成的名称、标题、正文与简介默认使用中文；作者另有语言要求时遵循其要求。

| 资料类型 | 建议小节 |
| --- | --- |
| 角色 | 身份与形貌、性情与所求、经历与关系、修为与手段 |
| 世界总览或规则 | 缘起与格局、运行法则、世间生活、矛盾与关联 |
| 宗门或势力 | 源流与立场、势力与传承、门规与日常、内外关系 |
| 地点或秘境 | 山川与景象、来历与人事、物产与机缘、往来与险阻 |
| 功法或器物 | 来历与形制、效用与用法、修习与成长、代价与局限 |

每条正文建议 **3–5 个小节**，上表按四节举例。先参考当前资料库同类条目的写法，标题可按内容改名或合并，不把每项属性再拆成下级标题。小节内用连贯文字展开，短条目不为凑数扩写，已有条目不强行重排。这些是写作方向，不是固定字段或逐项填写的表格。

导入后，在写作或游戏配置的项目对话中调用，例如：`使用 lore-creation，为玄霜岭创建一位经营雪舟的散修和他的船坞。沿用现有设定，分成角色与地点两条资料，写清小节并保存。` 也可要求只生成草稿，或补全一个已有角色的经历与功法限制。

Skill 会先查询并读取相关资料全文，再通过 `write_lore_items` 保存并读回核对，避免同名重复与整段覆盖时丢失旧设定。游戏中的伤势、库存、突破、死亡或关系进展留在各故事线；共享资料只保存稳定设定及明确标注的起始参考。没有资料工具或目标项目时只交付草稿，不声称已保存；安装本身不会改写资料，也不在游戏进行中开放配置写入。若另有整理索引的要求，沿用现有 `configuration` Skill，不把创建模板塞入全局常驻索引。

### 预设资料索引

导入资料时同时带入可编辑的索引，写作与游戏共用。六组按以下顺序展示：

| 分组 | 资料数 | 默认展示 |
| --- | ---: | --- |
| 世界总览 | 1 | 全文 |
| 修行与世道 | 11 | 简介 |
| 宗门与势力 | 13 | 简介 |
| 山河与秘境 | 12 | 简介 |
| 人物群像 | 31 | 简介 |

各组说明与条目简介提供查阅线索，正文通过资料工具按需读取。人物的初始境界、身份和关系作为背景参考；游戏沿用本故事已确认的进展，写作遵循作者指定的设定与时间线。

索引随 `lore.collection` 分发：`lore.json` 的 `index_guide.groups` 保存有序分组与说明，各条目的 `index_memberships` 保存关联并继承组默认展示级别。分组 ID 使用 `cultivation-` 前缀。阅读说明放在本包分组内，不依赖作品的全局阅读指引，也不修改整本书的自动分组展示默认值。

需要支持资料索引的 Denova 版本。用户可在资料库的「资料索引」中调整分组与展示级别；关联自定义分组期间，实际注入以分组及逐项设置为准。移出自定义分组后，条目按保留的加载方式回到自动分组。导入更新保留已有分组设置，本地修改过的条目遵循现有冲突处理规则；将资料更新应用到已有作品后，后续写作与游戏回合会使用更新后的索引，已有故事配置与历史内容不被重写。

### 使用与验证

资源包通过 `game_defaults` 声明推荐搭配：`lore` 中 `world` 条目的通用背景、`narrative` 叙事风格、`actor-state` 状态模板、`rules` 规则、`events` 事件包和 `illustration` 插图方案。普通导入不改变书籍配置；用户可按项采用为本书的新故事默认值，从资源包创建新书时会预选这些项。创建故事后可继续调整，已有故事配置与全局偏好保持不变，更新资源包不会重新应用推荐。插图方案的选择不会开启自动生图。

1. 在资源市场下载预览，选择目标书籍，导入世界资料，按需选装开局；可在集合预览内搜索、逐项阅读。
2. 在创作方案中选用“照夜长河”的叙事、状态、规则和事件预设，自定义角色与初始情境，或选用并编辑附带开局。导入本身不会替换已有故事配置或将旧故事迁入新设定。
3. 写作使用同一世界资料，按作者指定的主角、视角和范围创作；游戏使用原生状态和检定。
4. 采纳推荐背景后，新故事会预选“照夜长河·通用背景”，仍可调整或清空；附带的七张人物封面与五张背景无需现场生成。
5. 新生成插图需要图像模型，选择“照夜长河 · 仙途风华”并描述已经出现的场景。

例如：我扮演沈铸秋，从百炉城的一次工坊交货开始，沿用她的经历和修为，由我决定她的行动。也可以自行创建一名来自玄霜岭的散修，不与任何既有人物预设交情。


### 创作与分发

新增世界、人物、势力、功法和秘境均围绕本包原创设定创作，不搬用参考角色卡的人物、原文、图片、专有设定、脚本或提示词。创作内容和可编辑预设使用中文，市场介绍提供独立中英文版本，字段与枚举遵循协议。

`denova-pack.json` 同时承载市场介绍与资源列表；市场索引只登记来源。资料与开局分别保持一个 `version: 1` 集合文件，资料集合在 `items` 之外包含 `index_guide`，不新增资源类型、运行引擎或脚本。包版本为 `2.4.0`，保留包身份、资源 ID、默认背景与已有素材文件，只追加四张场景背景，不自动迁移用户既有故事。

## 扩展示例 · 文本统计与邻里来信

包内是两个可独立安装的扩展，没有彼此依赖。

### 文本统计

安装后在 Denova 中启用对应插件及工具集，需要本机 Node.js。工具接受直接传入的文本，不读取文件、不调用模型。

返回：
- `characters`：非空白字素簇数量，组合字符和家庭 emoji 按一个字素簇处理。
- `wordSegments`：Unicode 词语边界片段，使用 `Intl.Segmenter('en')`，不是模型 token 数，也不是统一的中文出版字数。
- `paragraphs`：空行分隔的非空段落。
- `sentences`：包含文字或数字的 Unicode 句子分段。

单次输入上限为 100,000 个 UTF-16 代码单元。原插件 ID 保持 `index.text-statistics`；已有独立安装可能需要先在导入界面处理原来源的归属冲突。

### 邻里来信 / Small Circle

一个现代生活题材的微信式社交模拟游戏。你刚搬进梧桐里，设计师林蔓、咖啡店主许宁和摄影师唐越正在筹备周末影展。

- **对话列表**：联系人搜索、最近消息、未读提示。
- **私聊**：自由输入、角色独立记忆、流式回复、停止回复、加载更早历史；切换联系人保留各自当前页面的输入草稿。
- **朋友圈**：三条原创开场动态、用户发布动态、点赞和评论。评论动态时由动态作者回复；评论自己的动态时可选择邀请哪位联系人回复。
- **联动**：角色能看到最近八条公开动态及当前评论目标；其他联系人的私聊不会传入其上下文。AI 评论保留在角色会话中，朋友圈保存其完成引用。初版不会自行定时发布 NPC 动态或后台发消息。
- **恢复**：已接受的请求保存稳定编号，刷新或断线后恢复原请求；回复失败或进程中断不会自动再次生成。保存冲突必须重新读取最新进度。聊天正文由 Denova 保存，游戏不另外复制一套聊天记录。
- **外观**：中英文、明暗主题、桌面对话分栏与手机单页导航。用户自由输入和既有模型回复保持原语言，切换界面语言不会改写历史。

安装时授权 `agents.run` 和 `gameData`。新建故事线时选择“邻里来信”，为“角色对话模型”选一个文本模型。模型配置及凭证由 Denova 管理，游戏没有自己的 API Key 输入框，也不需要 Node 后端。

这个游戏使用原创人物和本地游戏数据，不连接真实微信账号。文本统计插件是否安装，不影响游戏运行。
