# 示例资源包

## 照夜长河 · 大世界修仙模拟

定位是可长期生活与发展的**大世界修仙模拟设定**。从凡人问仙走到宗门晋升、散修经营、百艺传承、跨域远游，乃至渡劫飞升；没有唯一主线，也不要求玩家集齐人物、榜单或秘境。世界通过时间、资源、人物动机与已经发生的事实保持连续。

### 世界与成长

| 区域 | 生活与资源 | 势力及长期矛盾 |
| --- | --- | --- |
| 东陵 | 入门修炼、宗门生活、丹药与坊市 | 悬锋剑宗、合欢宗、抱朴谷、宋氏与千灯楼；峰脉、师承与资源竞争 |
| 赤砾原 | 炉城、矿路、器材与匠艺 | 百炉盟；公共炉位、矿供与新旧工艺 |
| 玄霜岭 | 雪舟、寒玉、药谷与人妖边市 | 寒汀门和霜羽盟；矿业、雷流与迁徙界约 |
| 沧溟海 | 航海、养珠、海药与遗府 | 潮生会和鲛绡庭；航路、产珠海沟与救援 |
| 中土 | 进阶传承、跨域阵台与护界 | 镜川书院、归衡院及灰契社；知识、禁术与接引资源 |
| 青阙仙域 | 仙元转化、界航与仙材研究 | 落星接引司、照界园；接引、居留与修行投入 |

统一序列：凡人 → 炼气一至十层 → 筑基 → 金丹 → 元婴 → 化神 → 返虚 → 合体 → 大乘 → 渡劫 → 真仙 → 仙帝 → 超脱。渡劫是飞升阶段，没有初中后期；其余分期及能力依资料说明。仙境仅保留这三境，不细分小境界，内容以凡界为重。

功法区分初学、熟练、精通，记录可用招式与剩余瓶颈；剑诀、合欢修法各有分支、配套与弱点，旁门传承提供有代价的选择。成长包含功法、身体与心神、资源、时间、护持和实际瓶颈。境界寿元不等于固定死亡日期，突破不会把年龄归零；高阶能力也有距离、承载与消耗。灵根、体质、神魂、丹器符阵、器物使用与宗门贡献各有资料，不以一次高点数替代必要条件。

### 可选开局与自定义角色

| 开局 | 初始处境 | 眼前选择 |
| --- | --- | --- |
| 凡人·山村问仙 | 成年药铺学徒，未引气、未测灵，升仙舟次日将行 | 陆照棠以半册功法交换藏身一夜 |
| 合欢·初入红尘 | 炼气二层外门弟子，尚无同修搭档 | 阮绯舟邀约试法，纪含章提醒往事 |
| 剑宗·败峰新徒 | 炼气二层藏锋崖新徒，刚拿到修好的旧剑 | 顾停云提出用修缮费换一次假赛 |

这三个只是便于开始的可编辑预设，不是资料库规定的角色或路线。用户可以创建自己的角色，也可以扮演陆照棠、阮绯舟等既有人物，自定合理的地域、境界、时间与处境。具体身份、初始行装、相遇场面和倒计时只写在所选预设或用户自定义内容中。选为玩家角色的人物不再作为独立 NPC 行动；未明确修改的经历与关系可以沿用，行动与选择仍由用户控制。

### 世界如何推进

- **时间与人物**：长时间闭关、养伤或远行前核对补给、年龄和到期约定。只推演有关人物与势力的有限变化：修炼、迁居、继承、经营、失利或衰老；不逐日生成全世界流水账，也不让所有人等待玩家。
- **信息与因果**：通过见证、传讯、公告和现场痕迹获知远方结果，消息会滞后。高阶人物也不能读取全部秘密，追索必须有信息、能力和时间。
- **秩序与风险**：宗门、坊市和荒野的保护不同。失败可以损失材料、受伤、被俘，明确的致命风险也可导致死亡；不凭空救援，不因普通失误随意判死。原生规则使用 `hard_failure`，后果与实际风险相称。
- **经营与生活**：价格有当地基准，产业需材料、租金、维护和合伙分成。记录净收益，允许稳定生活与真实成果，不自动无限产钱，也不每次休息都派人夺宝。
- **世界连续性**：死亡、离宗、突破、宝物易主和秘境采掘结果留在本故事。十二年后再进沉霞丹府，不会重置已取走的异火本源。榜单只是公开消息形成的评议，不是全知实时面板。

这是交给模型和 Denova 原生工具使用的设定与预设，**不是新开发的自动世界模拟引擎**。没有现实时间后台推进、独立排行榜数据库、HTML 状态栏或旧变量补丁协议。

### 可反复参与的玩法

- **修行**：先确定一个可观察的成果，再选择静修、求教、历练或同修；结算耗时与积累，已解决的瓶颈不会无故重置。平稳修炼可合并推进，突破后展示实际新能力。
- **功法**：引灯诀用于感气与恢复；听隙剑诀可从留半步发展到听阵、回澜，形成应对不同敌手的办法；心弦合息诀可走独修辨念或同修配合。招式有用法、条件与弱点，不只更换名称。
- **探索**：可选择外围取药、深入取传承、合作分火或勘路后撤。成果能炼化、修复、交易和投入下次行动；对手也会行动，秘境不会无限重置。
- **宗门**：比试、作品考核和长期职役都能提供资源与权限。接任后可授业、安排有限人手或经营资源，责任与收益一起变化。
- **经营**：明确一批订单的工时、成本、产量与售价。例如十四枚灵石成本、六颗丹每颗三枚，全售净余四枚；未售库存不当作收入。改良、复购和设备影响后续生产。
- **交游与生活**：同伴主动邀练、传讯、探望或商议合作；分工、合击、共享洞府与经营产生实际收益，情缘与信任从经历发展。灵兽可以培养寻踪、护送、采集等专长。

内容回归时关注这些场景：自定义高阶人物不退回新人身份；一次静修兑现约定成果；少成丹按实际批次结算；秘境提前撤离保留已得收益；扮演既有人物时不出现同名 NPC；两榜更新必须有公开消息。这些是实际模型试玩的检查点，静态资源与导入测试不证明长期叙事效果。

### 人物、秘境与长期目标

共 31 位人物。条目中的年龄、境界和身份是故事起点或初遇参考，不是终身定值；若已有时间推演，初遇时沿用推演结果。人物可从筑基逐步修至金丹乃至仙帝或超脱，也可能停滞、跌境或身亡，各故事线独立发展。当前境界、能力、寿元和职责以本故事已确认进展为准，不因重读资料回退，不回写共享资料。

东陵的陆照棠、阮绯舟、祝清砚等关系继续保留；各域新增不同阶段的人物，从器师沈铸秋、阵师江雁回、鹿族向导祁朔，到归衡院商听岚、大乘闻既明和仙界研究者沈问灯。每人有能力边界、眼前目标、习惯与既有关系，可与玩家合作、竞争或各自生活。

八处试炼与探索节点各有进入条件、时序、退路和收益：问剑旧台、沉霞丹府、烬轮窟、北天镜湖、潮返岛与沉舟庭、断穹古道、望阙台、照界园。其中望阙台和照界园是受管场所，不伪装成无人认领的宝箱。部分可多人有所获，部分核心资源有限，合作与独占会留下不同后果。

千灯楼只编撰天骄榜与绝色榜。天骄榜连接公开战绩、同辈挑战与招揽，绝色榜连接风姿、才艺、宴请与人情；名次不决定胜负或感情。宝物和异火保留来源、能力、归属与培养方式，价值依据实际用途判断。人物感情基于相处，亲密关系参与者均为成年人并自愿选择。

### 内容与文件

- `lore.json`：114 项，含 29 项世界与修行资料、14 个势力、19 处地点、31 位人物、21 项功法器物。正文约 3.21 万字符；仅世界总览常驻，其余按需读取，保留原有资料 ID。
- `openings.json`：三个可选开局，依赖资料集合；资料集合不依赖或指定其中任何开局。
- `narrative.json`：大世界模拟、时间推演、人物自主目标、视角和玩家控制边界。
- `actor-state.json`：13 个原生字段，覆盖境界、功法、位置、伤势、财物、约定、交游、时历、年龄寿元、资质、灵力心神、身份贡献及洞府产业。不把所有世界人物复制到玩家状态。
- `rules.json`：依据实际能力和准备处理不确定性，允许真正失败与相称后果。
- `events.json`：18 类际遇；在原有 12 类上加入经年闭关、跨域远行、产业经营、界约谈判、传承交接和飞升。事件只在条件成立时使用，不是自动倒计时。
- `illustration.json`：覆盖五域与仙界的场景和人物连续性。
- `skills/book-analysis/`：独立的通用中文拆书 Skill，适用于各种小说题材。

内容控制在五万字以内。测试采用更保守的计数：上述七个内容 JSON 的所有字符串值（连同名称、关键词、ID 等）加拆书 Skill 全文，不超过 50,000 个 Unicode 字符；不计 JSON 结构、分发元数据、许可证和本说明文档。避免将中文“字数”误写成模型 token 数。

### 使用与验证

1. 在资源市场下载预览，选择目标书籍，导入世界资料，按需选装开局；可在集合预览内搜索、逐项阅读。
2. 在创作方案中选用“照夜长河”的叙事、状态、规则和事件预设，自定义角色与初始情境，或选用并编辑附带开局。导入本身不会替换已有故事配置或将旧故事迁入新设定。
3. 写作使用同一世界资料，按作者指定的主角、视角和范围创作；游戏使用原生状态和检定。
4. 插图需要图像模型，选择“照夜长河 · 仙途风华”并描述已经出现的场景。

例如：我扮演沈铸秋，从百炉城的一次工坊交货开始，沿用她的经历和修为，由我决定她的行动。也可以自行创建一名来自玄霜岭的散修，不与任何既有人物预设交情。

`npm test` 检查资源结构、引用与内容体积。Denova 的 `TestIndexExamplesValidation` 可在隔离临时数据中验证预览、导入、导出与再次预览；这些检查不代替真实模型的长期游玩验证。

### 创作与分发

新增世界、人物、势力、功法和秘境均围绕本包原创设定创作，不搬用参考角色卡的人物、原文、图片、专有设定、脚本或提示词。创作内容和可编辑预设使用中文，市场介绍提供独立中英文版本，字段与枚举遵循协议。

`denova-pack.json` 同时承载市场介绍与资源列表；索引只登记来源。资料与开局分别保持一个 `{ "version": 1, "items": [...] }` 集合文件，不新增运行引擎或脚本。此次更新未发布示例，保留包身份与资源 ID，不自动迁移用户既有故事。

## 扩展示例 · 文本统计与邻里来信

包内是两个可独立安装的扩展，没有彼此依赖。

### 文本统计

安装后在 Denova 中启用对应插件及工具集，需要本机 Node.js。工具接受直接传入的文本，不读取文件、不调用模型。

返回：
- `characters`：非空白字素簇数量，组合字符和家庭 emoji 按一个字素簇处理。
- `wordSegments`：Unicode 词语边界片段，使用 `Intl.Segmenter('en')`，不是模型 token 数，也不是统一的中文出版字数。
- `paragraphs`：空行分隔的非空段落。
- `sentences`：包含文字或数字的 Unicode 句子分段。

单次输入上限为 100,000 个 UTF-16 代码单元。原插件 ID 保持 `index.text-statistics`；已有独立安装可能需要先在导入界面处理原来源的归属冲突。

### 邻里来信 / Small Circle

一个现代生活题材的微信式社交模拟游戏。你刚搬进梧桐里，设计师林蔓、咖啡店主许宁和摄影师唐越正在筹备周末影展。

- **对话列表**：联系人搜索、最近消息、未读提示。
- **私聊**：自由输入、角色独立记忆、流式回复、停止回复、加载更早历史；切换联系人保留各自当前页面的输入草稿。
- **朋友圈**：三条原创开场动态、用户发布动态、点赞和评论。评论动态时由动态作者回复；评论自己的动态时可选择邀请哪位联系人回复。
- **联动**：角色能看到最近八条公开动态及当前评论目标；其他联系人的私聊不会传入其上下文。AI 评论保留在角色会话中，朋友圈保存其完成引用。初版不会自行定时发布 NPC 动态或后台发消息。
- **恢复**：已接受的请求保存稳定编号，刷新或断线后恢复原请求；回复失败或进程中断不会自动再次生成。保存冲突必须重新读取最新进度。聊天正文由 Denova 保存，游戏不另外复制一套聊天记录。
- **外观**：中英文、明暗主题、桌面对话分栏与手机单页导航。用户自由输入和既有模型回复保持原语言，切换界面语言不会改写历史。

安装时授权 `agents.run` 和 `gameData`。新建故事线时选择“邻里来信”，为“角色对话模型”选一个文本模型。模型配置及凭证由 Denova 管理，游戏没有自己的 API Key 输入框，也不需要 Node 后端。

这个游戏使用原创人物和本地游戏数据，不连接真实微信账号。文本统计插件是否安装，不影响游戏运行。

### 验证与本地预览

仓库根目录执行：

```sh
npm ci
npm test
npx playwright install chromium
npm run test:browser
npm run build
npm run preview
```

预览地址为 `http://127.0.0.1:4381`，采用明确的脚本测试回复，服务退出后测试数据消失。实际 AI 游玩需安装到 Denova。

有扩展平台的 Denova 源码时可运行：

```sh
npm run test:denova -- /absolute/path/to/denova
```

该验证会启动真实的隔离扩展页面与角色会话，模型使用测试替身，数据使用临时目录；不会读取或改变正常用户的数据目录。
