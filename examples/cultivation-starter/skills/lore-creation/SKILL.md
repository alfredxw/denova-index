# 资料创建

将作者的构想或提供的材料整理成可独立查阅、分节清楚的资料。本技能随修仙预设分发，但适用于各种题材，不依赖该预设的世界观。默认使用中文；作者另有语言要求时，名称、标题、正文和简介统一遵循该要求，同一份交付内容只使用一种语言。

## 确定范围与已有设定

- 遵循作者指定的对象、题材、详略和交付位置。要求创建项目资料时，可在当前工具允许的范围内直接保存；仅要求构思、草稿或审阅时，不改动资料库。
- 阅读相关创作要求和作者提供的材料。调用不带筛选条件的 `query_lore_items` 查看项目分类与条目名称；创建前查询可能重名的名称、别名和相关主题。需要更多结果时，沿用原筛选条件并按 `next_offset` 继续读取。精确查询 `ids` 或 `names` 不能混用搜索筛选条件。读取正文须指定 `detail=full`，默认的 `index` 只返回简介。
- 匹配到已有条目时复用其准确 ID，修改前先读正文。在作者授权的创作范围内扩充已确认的设定，不把待定方案、传闻或可能发生的未来写成既定事实。仅当缺失的选择会实质改变结果时询问，其余细节根据构想合理展开。
- 每条资料只写一个角色、实体或完整的设定主题。同一对象的相关事实放在一起，可独立查阅的人物、地点和体系拆成不同条目。使用 `[[准确的资料名称]]` 引用已有或本次一同创建的条目；引用不会自动加载目标正文。

## 选择小节并编写

通过 `read` 只读取当前任务需要的指南：

- 角色 → `skill://lore-creation/references/characters.md`
- 世界规则、势力、地点、功法与器物 → `skill://lore-creation/references/settings.md`

每条正文建议使用 **3–5 个小节**，不把每个信息点都拆成标题，也不在小节里继续套多层提纲。先参考当前资料库中同类条目的写法，再按内容选择、改名或合并指南中的小节；指南是建议，不是必须逐项填写的表格。短条目无需为了凑数扩写，补全已有条目时也不为满足数量而强行重排。

身份、外貌、性格、经历、关系和能力可以在几个小节中自然展开。每节围绕一个清楚的主题，用连贯文字写有用的信息，不堆砌标签、空标题或泛泛的使用说明。

用具体行为、感官细节、关系和后果支撑设定。能力与规则应说明能做什么、需要什么代价、何时会失效。公开信息、隐秘事实和不确定说法会影响叙事或游玩时，应明确区分。互动可能只是机会，不是强制剧情，也不预定玩家选择。

## 区分共享资料与当前状态

资料保存稳定的身份、性格、背景、长期关系与世界运行规则。可以写起始年龄、境界和所属势力，但应标明所对应的起点，不能当作永久不变的数值。

- 写作中的当前位置、伤势、库存、短期目标和章节进展，放在已有的角色状态与进度文件中；章节计划放在大纲中。
- 游戏中某条故事线发生的突破、死亡、物品易主、探索结果与关系变化，保留在该故事已确认的状态或历史中。不能因重读资料而恢复为初始状态，也不能仅因回合推进就回写共享资料。游戏设定资料在创作配置场景中编写；本技能不会在游玩过程中授予写入工具。
- 除非作者明确要求该前提，否则不通过共享资料指定玩家身份、行动、关系或开局。某个人物被选为玩家角色后，不再另建同名 NPC。

## 保存与核对

作者要求保存且当前可用 `write_lore_items` 时：

1. 不同实体分别放入独立的 `items`。新建条目提供 `name`、以现有分类 ID 填写的 `type`、分节 Markdown 正文 `content` 和有查阅价值的 `brief_description`。标准分类为 `character`、`world`、`faction`、`location`、`item`，但应以当前项目分类目录为准，不能假定这些分类仍全部存在。具体功法通常归入物品，共通能力体系归入世界设定，不必为此新建分类。
2. 将 `brief_description` 写成简洁的查阅指引：先写类型与名称，再用 3–5 句话说明身份、独特事实、别名和何时需要查阅。`keywords` 只放有用的名称、别名与检索词；`tags` 用于有意义的共同分组。简介不重复整篇正文，也不把所有新条目都设为 `major` 或 `resident`。
3. 更新时提供已有条目的准确 `id`，只提交需要改动的字段。提交 `content` 会替换整篇正文，必须保留仍然有效的事实、关系和小节；事实变化时同步更新简介。省略数组会保留原值，显式空数组会清空。保留无关设置与素材，仅在作者明确要求删除时使用 `delete_ids`。
4. 检查工具结果，再按准确 ID 使用 `query_lore_items(detail=full)` 读回每条已保存资料，核对正文、简介与交叉引用是否符合要求。失败后先确认实际保存情况再重试，避免重复创建；不能仅凭尝试调用就声称保存成功。

不直接编辑 `setting/lore/items.json`，也不另建 `characters.md` / `world-building.md` 作为平行资料库。缺少资料工具或目标项目时交付草稿，并明确说明尚未保存。

索引分组与正文编写分开处理，新条目可以沿用自动分组。作者同时要求整理索引时，使用已安装且可用的 `configuration` 技能及其 `lore_index` / `lore_index_membership` 资源，保留已有分组和无关关联，不向 `write_lore_items` 传入索引字段。安装本技能本身不会创建或改写资料条目、索引分组。

完成后简要列出创建或更新的条目；如有待作者决定的事项或保存失败，一并说明。
